# QoE Prediction on the PoQeMoN Dataset

project: comparison of Machine Learning models for predicting the Mean Opinion Score (MOS, ranging from 1 to 5) of mobile video sessions using the [PoQeMoN QoE dataset](https://github.com/Lamyne/Poqemon-QoE-Dataset).

The objective is to investigate how application-level, network, device, user and subjective feedback features contribute to perceived video quality prediction.

## Dataset

The project uses the PoQeMoN mobile video QoE dataset.

The dataset contains:
- 1,543 video sessions
- 181 unique users
- 23 columns, including identifiers, input features and the MOS target
- Five MOS classes (1 to 5)
- No missing values

The target variable is `MOS`, representing the user's overall perceived video quality.

The MOS distribution is imbalanced, with MOS 4 being the most frequent class.

No manual download is required. On the first run, the notebook downloads `pokemon.csv` from:

[Download source CSV](https://raw.githubusercontent.com/Lamyne/Poqemon-QoE-Dataset/master/pokemon.csv)

The file is cached in the `data/` directory, which is excluded from Git.

To work offline, place the dataset manually at:

`data/pokemon.csv`

## Feature Sets

Two feature sets are compared:

| Feature set | Included features | Number of features |
|---|---|---:|
| `objective` | QoA, QoS, QoD and QoU | 16 |
| `with_feedback` | Objective features + QoF subjective ratings | 20 |

The objective feature set evaluates MOS prediction using measurable application, network, device and user characteristics.

The second feature set additionally includes subjective QoF ratings (`QoF_begin`, `QoF_shift`, `QoF_audio` and `QoF_video`) to investigate their contribution to prediction performance.

## Models and Evaluation

Six classification algorithms are compared:

- Dummy Classifier (majority-class baseline)
- k-Nearest Neighbors (kNN)
- Support Vector Classifier (SVC)
- Decision Tree
- Random Forest
- XGBoost

Hyperparameter tuning is performed using `GridSearchCV`.

Macro-F1 is the primary model selection metric because of the imbalanced MOS distribution.

Additional evaluation metrics include:
- Accuracy
- Balanced Accuracy
- Mean Absolute Error (MAE)

The analysis also includes confusion matrices, classification reports and permutation feature importance.

## Experimental Protocol and Reproducibility

The experiments use the following configuration:

- Random seed: `SEED = 42`
- Target: `MOS` (encoded from classes 1–5 to 0–4 for model compatibility)
- Train/test split: one stratified, user-grouped split using `StratifiedGroupKFold` with 5 folds
- Held-out test set: 304 sessions from 33 users
- Training set: 1,239 sessions from 148 users
- User separation: no user appears in both training and test sets
- Hyperparameter tuning: 5-fold `StratifiedGroupKFold` cross-validation on training users
- Model selection: highest mean cross-validation Macro-F1
- Preprocessing: scaling, log transformation of selected skewed features and one-hot encoding, implemented within a pipeline to prevent data leakage

Each model's best hyperparameter configuration is refitted on the complete training set and evaluated once on the held-out test set.

The notebook also includes a repeated cross-validation experiment (five repetitions of five folds) comparing random stratified splitting with user-grouped stratified splitting.

Grouped splitting is preferred because the intended objective is to assess generalization to previously unseen users.

Package versions are listed in `requirements.txt` and printed by the notebook.

## Notes and Limitations

The dataset is relatively small and has an imbalanced MOS distribution. Therefore, performance estimates, especially for minority classes, should be interpreted with caution.

The `with_feedback` experiment uses subjective QoF ratings that may not be available in an automatic QoE prediction scenario. Their relationship with the MOS target should also be considered when interpreting the results.

All preprocessing and hyperparameter selection are performed within the training data. The held-out test set is reserved for final model evaluation.
